# HiHana Evo 오프닝 애니메이션 — 최종 납품 (시안 A "Weave")

로고의 세 갈래(민트·인디고·코랄)가 거의 동시에 **카메라(눈) 바로 앞을 스치듯 크게** 나타납니다.
이어서 멀어지며 작아지고, 가늘고 긴 실크 리본이 되어 **자리에 닿는 부분부터** 로고 조각의 형태로 감싸지며 완성됩니다.
천은 처음 들어올 때 넓게(한 갈래가 화면의 26–38%) 크게 펄럭이고, 멀어지며 가늘어지고 잦아듭니다.
민트와 코랄이 먼저 자리를 잡고, 인디고 다리는 코랄의 앞면·뒷면 사이로 꿰어 들어와 0.32초 뒤에 자리를 잡습니다. 마지막에 다리가 혼자 메꿔지는 구간은 없습니다.
완성 후에는 2.2% 숨쉬기 한 번과 대각선 하이라이트가 한 번 지나갑니다.

- **A. Lottie** `lottie/opening.json`
  - 8.27 MB, 순수 벡터, 배경 투명 (수정 2회차에서 의뢰인 요청으로 1.5 MB 제한을 일단 해제)
- **B. Jetpack Compose** `compose/EvoOpening.kt`
  - 같은 수식으로 직접 그리고, 글자·배경·페이드·탭·햅틱을 포함합니다.
- 두 형태는 같은 모션 엔진(`lottie/source/`)에서 나옵니다.
  - Lottie는 엔진의 기하를 키프레임으로 베이크한 것입니다.
  - Compose는 같은 수식을 Kotlin으로 옮긴 것이고, Python 엔진과 수치가 0.3 로고 단위(0.3px) 이내로 일치합니다.

## Lottie 사용 기능 / 금지 기능 확인

**사용한 기능**
- 셰이프 레이어: 그룹 `gr`, 경로 `sh`의 정점·핸들 키프레임(선형 보간), 변형 `tr`
  - 세그먼트마다 그룹 두 겹입니다. 바깥 그룹 변형(위치·회전·비균등 배율)과 안쪽 그룹 회전이 함께 세그먼트의 아핀 `A = R(φ)·diag(s1, s2)·R(θ)`를 만듭니다.
  - 경로는 그 아핀을 되돌린 로컬 좌표로 넣습니다. 화면에서의 모양은 엔진과 같습니다(오차 0.2 로고 단위 이하).
- 선형 그라데이션 필 `gf` — 색·정지점은 모두 정적입니다.
  - 바탕: 부록 그라데이션 그대로(시작·끝점도 정적)입니다. 그룹 변형이 아핀으로 기울이고 늘이므로, 엔진의 아핀 맞춤 그라데이션과 같습니다.
  - 천의 명암(빛·그늘·뒷면): 로컬 좌표의 흰색·검정 램프 4개(앞 끝 1→0, 뒤 끝 0→1)를 겹치고, 필 불투명도 키프레임으로 세기를 바꿉니다. 두 램프를 a0, a1로 겹치면 a0 → a1 선형 명암이 됩니다.
  - 램프 축은 평소엔 고정입니다. 그룹 아핀이 크게 찌그러져 고정 축의 명암이 엔진과 2% 넘게 달라지는 프레임에서만, 엔진의 화면 공간 램프와 정확히 같아지는 로컬 끝점(`s = A⁻¹(p0 − t)`, `e = s + g/|g|²`, `g = Aᵀd/|d|²`)으로 움직입니다.
  - 접힘: 필 불투명도 키프레임 (명암 덮개에도 곱함)
- 레이어 부모(null 레이어 `ty 3`), 레이어 in/out 지점, Composition Markers
- 포맷: Bodymovin `5.7.4`, 1080×2340, 60fps, 420프레임, 배경 레이어 없음(투명), 이미지 에셋 없음, 8,265,504 bytes
- 그라데이션 색은 반올림하지 않은 값(k/255)으로 넣었습니다. lottie-android가 (int)(v·255)로 잘라도 부록 색 그대로 나옵니다.

**쓰지 않은 금지 기능**
- 익스프레션 0개 (`"x"` 키 없음)
- AE 이펙트 0개 (`"ef"` 없음). Turbulent Displace·Puppet·Mesh Warp 없이 모든 왜곡과 흩날림을 경로 키프레임으로 베이크했습니다.
- 트랙 매트·마스크·트림 패스도 쓰지 않았습니다. 하이라이트는 매트 대신 실루엣 경로에 그라데이션을 채웠습니다.
- lottie-android 6.7.1 로드 시 경고 0건 (`composition.getWarnings()`)

**크기를 줄인 방법**
- 키프레임은 매 프레임이 아니라, 선형 보간 오차가 0.2 로고 단위(0.25px) 이하로 유지되는 시점에만 둡니다.
- 경로, 변형, 명암 불투명도는 속성마다 따로 단순화합니다.
- 명암 불투명도는 세그먼트가 화면 밖에 있는 동안 키를 두지 않습니다. 경로·변형은 둘의 보간이 화면 안으로 튀지 않도록 화면 밖에서도 키를 둡니다.

## Compose 구현 핵심

1. **재료 좌표**: 각 갈래를 띠로 보고 (u 길이, v 폭) 좌표를 붙입니다. 착지 모양 `P(u, v)`는 부록 벡터의 정확한 점이고, 사선 단면이 로고의 끝 컷과 나란합니다.
2. **비행과 원근**: 섹션 u는 `ts(u) = T0 + κ·w(u)`부터 감쇠 스프링(ζ = 0.9)으로 접근 경로를 따라 날아옵니다.
   - 섹션마다 원근 배율 `ps = 1 + 7·(1 − r)²`(출발 8배 → 착지 1배)를 로고 중심 기준으로 곱합니다. 그래서 카메라 바로 앞을 크게 스친 뒤 멀어지며 작아집니다. 출발 직전에는 카메라 뒤(21배)에 있어 화면에 보이지 않습니다.
   - 경로는 화면 경유점(눈앞을 지나는 위치)에서 거꾸로 풀어 정합니다(`choreo.screen_path`).
   - 비행 중에는 폭 46–48(로고 단위, 원근 배율 전)의 띠이고, 끝으로 갈수록 가늘어집니다.
     - 막 들어올 때는 폭에 `1 + wide·(1 − r)^1.5`(wide 2.6–3.0)를 곱해 넓게 펼칩니다. 멀어질수록 원래 폭으로 돌아옵니다.
   - **천의 명암**: 왼쪽 위 앞쪽 조명 기준으로 천 면의 기울기(비틀림·물결로 정해짐)에서 빛과 그늘을 계산합니다.
     - `명암 = K_DIFF·(n·L − 0.55) + K_SPEC·(max(0, n·H)^8 − H_z^8)`
     - 휘는 곳과 물결 마루에 부드러운 새틴 하이라이트가 생기고, 돌아선 곳과 뒷면은 그늘이 집니다.
     - 세그먼트마다 흰·검정 램프로 칠합니다. 램프 축을 경계선에 맞춰 세그먼트 사이 명암이 이어집니다.
     - (1 − α)로 착지하면 0이 되어, 완성 로고 색은 원본 그대로입니다.
   - **바람**: 먼저 닿는 앞 끝에서 자유로운 뒤 끝으로 흐르는 물결 3개(위상 `k·d − f·t`)가 뒤 끝일수록 크게 칩니다. 돌풍 `g(t)`로 세기가 출렁입니다.
     - 세기에 `1 + 1.2·(1 − r)²`를 곱해, 막 들어온 넓은 천일수록 크게 펄럭입니다.
     - 옆 흔들림과 길이 방향 출렁임이 있습니다.
     - 면이 기울어 폭이 좁아지는 마디가 물결을 따라 흐릅니다.
     - 두 가장자리가 따로 출렁이고(폭 출렁임) 단면이 비스듬히 밀립니다.
     - 모두 착지할수록 0이 되어, 멈춘 뒤에는 원본 벡터 그대로입니다.
   - 뒷면(cosθ < 0)은 최대 28% 어둡게 칠합니다.
3. **형태 잡힘**: `X = O + (1 − α)·비행모양 + α·P(u, v)`입니다.
   - 제자리 몇십 px 안에 들어온 섹션부터 α가 0→1로 오릅니다.
   - α는 바깥 가장자리부터 안쪽으로 오르므로, 실크가 보이지 않는 형태를 덮듯 내려앉습니다.
   - 멈추면 `X = P` 그대로이고, 그 뒤에는 부록 경로를 그대로 그립니다.
4. **그리기**: 면을 u 띠 세그먼트로 나눕니다.
   - 세그먼트마다 3차 베지어 경로를 워프합니다. 앵커는 워프하고, 핸들은 변위의 곡선 방향 미분으로 보정합니다.
   - 그라데이션은 최소제곱 아핀 맞춤으로 따라갑니다. 셰이더 행렬이 그 아핀 전체여서, 비틀린 면에서는 등색선도 함께 기웁니다. 음영은 선형 램프로 칠합니다.
   - `Path`·`LinearGradient`·`Matrix`·`Paint`는 처음에 만들어 재사용합니다. 경로 파싱과 표 계산은 시작할 때 한 번만, `Dispatchers.Default`에서 합니다(그동안 배경만 표시). 프레임당 할당이 없습니다.
5. **시간**: `Animatable` 하나(선형, 7.0초)를 `drawBehind`와 `graphicsLayer` 람다에서만 읽어 재구성이 없습니다.
   - 시스템 애니메이터 길이 배율이 0이면 완성 로고와 글자를 1.4초 보여 주고 끝냅니다.
   - 화면이 뜬 지 0.6초 이후의 탭만 즉시 `onFinish()`를 호출합니다('애니메이션 끄기'여도 같음). `onFinish()`는 한 번만 호출됩니다.

API: `Path`, `LinearGradient`, `Matrix`, `Canvas.drawPath`만 씁니다(API 1+). `drawVertices` 같은 API 29+ 전용 기능은 쓰지 않으므로, minSdk 26–28에서도 같은 경로로 그립니다. 새 라이브러리 없이 Compose BOM 2026.08.00 + material3만 씁니다.

**돌려 보지 못한 것**
- **실제 안드로이드 기기·에뮬레이터**: 작업 환경에 기기와 KVM이 없어 에뮬레이터를 띄울 수 없었습니다.
  - 그래서 `compose.mp4`는 기기 녹화가 아니라 Robolectric(안드로이드와 같은 Skia를 CPU에서 실행) 녹화입니다.
  - GPU(HWUI) 렌더와는 안티앨리어싱이 미세하게 다를 수 있습니다.
  - 글꼴은 Robolectric 기본 Roboto라서, 기기 글꼴로 보면 한글 소개 문구 모양이 조금 다릅니다.
  - 녹화에서는 앱의 투어 화면 대신 #0B0B1A 단색을 깔았습니다.
- **중급 폰 60fps**: 실기기 프로파일링을 하지 못했습니다.
  - 코드상으로는 프레임당 할당과 파싱이 없습니다.
  - 매 프레임 계산량은 리본 3개 × 257단면 갱신(바람 포함)과 세그먼트 77개의 워프입니다.
  - 그리기는 `drawPath` 최대 약 230회(세그먼트 77 × 바탕·그늘·빛)이고, 착지가 끝나면 6회로 줄어듭니다.
  - 무겁다면 `choreo.py`의 `K`(세그먼트 수)를 12/10/12로 낮추면 됩니다.
  - Snapdragon 7 계열 기기에서 GPU 렌더링 프로파일로 한 번 확인해 주세요.
- **햅틱 체감**: JVM에서는 호출만 기록되고 진동은 나지 않습니다.
- **lottie-android 실기기 재생**: 같은 라이브러리를 JVM에서 돌렸습니다. 하드웨어 가속 캔버스에서의 재생은 직접 확인하지 못했습니다.

## 알아 둘 점 — lottie-android 의 그라데이션 캐시

lottie-android(6.7.1)는 그라데이션 셰이더를 재생 진행도 32ms 단위로 캐시합니다(`GradientFillContent.getGradientHash`).
- 그라데이션의 시작·끝점이나 색을 키프레임으로 움직이면, 60fps에서 두 프레임 중 한 프레임이 직전 프레임의 그라데이션을 그대로 씁니다.
- 그래서 움직임은 그룹 변형이 맡고(캐시 대상 아님), 명암 세기는 필 불투명도가 맡습니다(매 프레임 적용). 색과 바탕 그라데이션은 정적입니다.
- 명암 램프의 끝점만은 아핀이 크게 찌그러지는 프레임(주로 천이 카메라 바로 앞을 지나는 0.3–0.7초)에 움직입니다. 고정 축을 쓰면 그때 빛과 그늘이 통째로 뒤바뀌기 때문입니다.
  - 그 구간의 8프레임(f24–41)은 순서대로 재생하면 램프 끝점이 한 프레임(16ms) 늦습니다. 엔진과 다른 화소는 화면의 1–13%이고, 가장 큰 것은 f29입니다. 같은 프레임을 단독으로 그리면 엔진과 같습니다(f26: 49 px).
  - 나머지 프레임은 엔진(= Compose) 렌더와 다른 화소가 프레임당 3.1천 px(0.1%) 이하이고, 대부분 가장자리 안티앨리어싱입니다.
  - 고정 축만 쓰던 이전 판은 이 구간 전체(0.27–0.67초)에서 빛과 그늘이 뒤바뀌었습니다(최대 화면의 31%).

## 다시 만들기

```bash
cd lottie/source
pip install numpy skia-python pillow           # 엔진·미리보기 렌더 (skia-python 은 libEGL 필요)
python3 build_deliverables.py A --harness ../../verify
#  → lottie/opening.json, compose/EvoOpening.kt 의 생성 상수 블록, preview/*, build_report.json
```

- `verify/android`
  - Android SDK(`local.properties`의 `sdk.dir`)가 필요합니다.
  - `./gradlew :app:testDebugUnitTest --tests '*EvoParity*'|'*LottieRender*'|'*RecordFrames*'`로 개별 실행할 수 있습니다.
- `verify/web`: `npm ci` 후 `node render_lottie_web.mjs JSON OUTDIR --bg '#0B0B1A'`
- 연출 값
  - 연출 값은 `lottie/source/choreo.py` 한 곳에 있습니다.
  - Compose 쪽 숫자는 `gen_kotlin_consts.py`가 `EvoOpening.kt`의 `BEGIN/END 생성된 상수` 블록에 넣습니다. 손으로 고치지 말고 생성기를 돌려 주세요.

## 진행 기록

- 러프 2안을 비교했습니다: A "Weave"(대각선 양끝에서 끝부터 감싸기, 인디고가 꿰어 들어감)와 B "Breeze"(가운데부터 감싸기, 인디고가 아래에서 아치로 올라옴).
- 독립 검토 2건(브리프 준수, 모션 미감)이 모두 A를 추천했고, 공통 지적은 최종본에 반영했습니다.
  - 리본 끝 '부리' 모양을 없앴습니다.
  - 비틀림이 화면 안에서 보이게 하고, 풀림이 리본을 따라 번지게 했습니다.
  - 형태가 제자리 근처에서만 잡히게 했습니다.
  - 세그먼트 사이 색 줄무늬를 없앴습니다.
  - 착지 마커를 눈에 멈추는 시점으로 옮겼습니다.
- 의뢰인 선택은 A이고, B는 폐기했습니다.
- 수정 1회차(의뢰인 요청):
  - 천이 처음부터 너무 작다는 의견에 따라 1인칭 원근을 넣었습니다. 눈앞을 크게 스친 뒤 멀어지며 작아집니다.
  - 세 갈래의 등장 간격을 1.3초에서 0.2초 안으로 줄였습니다. 인디고는 더 느린 경로로 마지막에 착지합니다.
  - 부제를 'HiHana, 다시 한 번 진화하다'로 바꾸고 16sp에서 20sp로 키웠습니다.
- 수정 2회차(의뢰인 요청):
  - 천이 딱딱하다는 의견에 따라 바람 모델(흐르는 물결, 돌풍, 면 기울기, 가장자리 잔물결)을 넣었습니다.
  - 잔물결을 표현하려고 세그먼트를 20/16/20, 곡선 조각을 최대 24 단위로 늘렸습니다.
  - 1.5 MB 제한은 일단 고려하지 않기로 했습니다.
- 수정 3회차(의뢰인 요청):
  - 천이 단색이라 실제 천 같지 않다는 의견에 따라 조명 기반 명암을 넣었습니다(확산광 + 새틴 하이라이트 + 뒷면 그늘).
  - Lottie는 2.63 MB입니다.
- 수정 4회차(의뢰인 요청):
  - 마지막에 인디고 다리가 혼자 메꿔지던 약 1초를 없앴습니다. 인디고가 코랄보다 0.17초 늦게(2.10초) 자리를 잡고, 전체 길이는 6.5초에서 6.0초가 됐습니다.
  - 천이 처음 들어올 때 폭을 3.6–4배로 넓히고 바람 물결을 2.2배로 키웠습니다. 막 들어온 순간 한 갈래가 화면의 26–38%를 덮습니다(민트 27%, 코랄 38%, 인디고 26%).
  - 천이 넓고 빨라지면서 lottie-android의 그라데이션 캐시 지연이 보이게 되어, Lottie 구조를 그룹 변형 + 정적 그라데이션으로 바꿨습니다('알아 둘 점' 참고). Lottie는 4.61 MB입니다.
  - Compose의 바탕 그라데이션도 엔진·Lottie와 같은 아핀 전체 행렬로 맞췄습니다.
- 수정 5회차(의뢰인 요청):
  - 너무 빠르다는 의견에 따라 리본의 모든 움직임(비행·스프링·바람·비틀림)을 1.8배 느리게 했습니다. 착지는 3.30 / 3.47 / 3.78초입니다.
  - 숨쉬기와 하이라이트까지 1.8배로 늘리면 완성이 5.85초가 되어, 브리프의 '전체 6–7초, 완성 후 정지 1.5초 이상'을 함께 지킬 수 없습니다. 그래서 숨쉬기는 1.67배(1.0초), 하이라이트는 1.33배(1.2초)로만 늘리고 인디고 착지 직후에 겹쳐 시작합니다.
  - 전체 길이는 7.0초(브리프 상한), 완성 후 정지는 1.8초입니다. 글자가 다 떠오른 뒤 페이드까지는 약 0.5초입니다.
  - 느려진 근접 통과에서 Lottie의 명암이 엔진과 뒤바뀌는 문제를 찾아 고쳤습니다. 원인은 찌그러진 그룹 아핀이 고정 명암 램프의 등명암선을 기울인 것입니다. 그런 프레임에서는 램프 끝점을 정확한 로컬 값으로 움직입니다. Lottie는 8.27 MB입니다.
