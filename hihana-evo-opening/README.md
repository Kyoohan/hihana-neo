# HiHana Evo 오프닝 애니메이션 — 최종 납품 (시안 A "Weave")

로고의 세 갈래(민트·인디고·코랄)가 화면 밖에서 가늘고 긴 실크 리본으로 흩날려 들어와,
**자리에 닿는 부분부터** 로고 조각의 형태로 감싸지며 완성됩니다.
민트와 코랄이 먼저 각자 자리를 잡고, 인디고 다리가 코랄의 앞면·뒷면 사이로 실처럼 꿰어 들어와 마지막에 둘을 잇습니다.
완성 후에는 2.2% 숨쉬기 한 번과 대각선 하이라이트가 한 번 지나갑니다.

- **A. Lottie** `lottie/opening.json`
  - 1.25 MB, 순수 벡터, 배경 투명
- **B. Jetpack Compose** `compose/EvoOpening.kt`
  - 같은 수식으로 직접 그리고, 글자·배경·페이드·탭·햅틱을 포함합니다.
- 두 형태는 같은 모션 엔진(`lottie/source/`)에서 나옵니다.
  - Lottie는 엔진의 기하를 키프레임으로 베이크한 것입니다.
  - Compose는 같은 수식을 Kotlin으로 옮긴 것이고, Python 엔진과 수치가 0.02 로고 단위(≈0.02px) 이내로 일치합니다.

```
hihana-evo-opening/
  ├─ lottie/
  │    ├─ opening.json        Lottie 최종본 (6-A)
  │    └─ source/             작업 원본 — 이 툴(파이썬 모션 엔진)의 소스. build_deliverables.py 로 전부 재생성
  ├─ compose/
  │    └─ EvoOpening.kt       Compose 최종본 (6-B)
  ├─ preview/
  │    ├─ lottie.mp4          lottie-android 6.7.1 로 재생한 프레임 — H.264, 1080×2340, 60fps, 배경 #0B0B1A
  │    ├─ compose.mp4         EvoOpening 을 Robolectric(안드로이드 Skia, JVM)에서 프레임 단위로 녹화 — 아래 '재생 확인' 참고
  │    └─ keyframes/          핵심 장면 8장 (00_start ~ 07_final, 파일명 끝 _fNNN = 프레임 번호)
  ├─ verify/                  검증 하네스 (Robolectric + lottie-android, lottie-web)
  └─ README.md
```

## Lottie 사용 기능 / 금지 기능 확인

**사용한 기능**
- 셰이프 레이어: 그룹 `gr`, 경로 `sh`의 정점·핸들 키프레임(선형 보간), 변형 `tr`
- 선형 그라데이션 필 `gf`
  - 색 정지점 고정, 시작·끝점 키프레임
  - 비틀림 음영: 검정 + 불투명도 정지점 키프레임
  - 접힘: 필 불투명도 키프레임
- 레이어 부모(null 레이어 `ty 3`), 레이어 in/out 지점, Composition Markers
- 포맷: Bodymovin `5.7.4`, 1080×2340, 60fps, 390프레임, 배경 레이어 없음(투명), 이미지 에셋 없음, 1,253,797 bytes

**쓰지 않은 금지 기능**
- 익스프레션 0개 (`"x"` 키 없음)
- AE 이펙트 0개 (`"ef"` 없음). Turbulent Displace·Puppet·Mesh Warp 없이 모든 왜곡과 흩날림을 경로 키프레임으로 베이크했습니다.
- 트랙 매트·마스크·트림 패스도 쓰지 않았습니다. 하이라이트는 매트 대신 실루엣 경로에 그라데이션을 채웠습니다.
- lottie-android 6.7.1 로드 시 경고 0건 (`composition.getWarnings()`)

**크기를 줄인 방법**
- 키프레임은 매 프레임이 아니라, 선형 보간 오차가 0.3 로고 단위(0.37px) 이하로 유지되는 시점에만 둡니다.
- 경로, 그라데이션, 음영, 불투명도는 속성마다 따로 단순화합니다.
- 화면 밖에 있는 동안은 키를 두지 않습니다.

## Compose 구현 핵심

1. **재료 좌표**: 각 갈래를 띠로 보고 (u 길이, v 폭) 좌표를 붙입니다. 착지 모양 `P(u, v)`는 부록 벡터의 정확한 점이고, 사선 단면이 로고의 끝 컷과 나란합니다.
2. **비행**: 섹션 u는 `ts(u) = T0 + κ·w(u)`부터 감쇠 스프링(ζ = 0.9)으로 화면 밖 경로를 따라 날아옵니다.
   - 비행 중에는 폭 58–60(로고 단위)의 가는 띠입니다. 끝으로 갈수록 가늘어지고, 비틀림 θ와 흩날림이 리본을 따라 흐릅니다.
   - 뒷면(cosθ < 0)은 최대 28% 어둡게 칠합니다.
3. **형태 잡힘**: `X = O + (1 − α)·비행모양 + α·P(u, v)`입니다.
   - 제자리 몇십 px 안에 들어온 섹션부터 α가 0→1로 오릅니다.
   - α는 바깥 가장자리부터 안쪽으로 오르므로, 실크가 보이지 않는 형태를 덮듯 내려앉습니다.
   - 멈추면 `X = P` 그대로이고, 그 뒤에는 부록 경로를 그대로 그립니다.
4. **그리기**: 면을 u 띠 세그먼트로 나눕니다.
   - 세그먼트마다 3차 베지어 경로를 워프합니다. 앵커는 워프하고, 핸들은 변위의 곡선 방향 미분으로 보정합니다.
   - 그라데이션은 최소제곱 아핀 맞춤으로 따라가고, 음영은 선형 램프로 칠합니다.
   - `Path`·`LinearGradient`·`Matrix`·`Paint`는 처음에 만들어 재사용합니다. 경로 파싱은 시작할 때 한 번만 하고, 프레임당 할당이 없습니다.
5. **시간**: `Animatable` 하나(선형, 6.5초)를 `drawBehind`와 `graphicsLayer` 람다에서만 읽어 재구성이 없습니다.
   - 시스템 애니메이터 길이 배율이 0이면 완성 로고와 글자를 1.4초 보여 주고 끝냅니다.
   - 0.6초 이후 탭하면 즉시 `onFinish()`가 호출되고, `onFinish()`는 한 번만 호출됩니다.

API: `Path`, `LinearGradient`, `Matrix`, `Canvas.drawPath`만 씁니다(API 1+). `drawVertices` 같은 API 29+ 전용 기능은 쓰지 않으므로, minSdk 26–28에서도 같은 경로로 그립니다. 새 라이브러리 없이 Compose BOM 2026.08.00 + material3만 씁니다.

| `EvoOpening` 프레임 녹화 (`RecordFramesTest`) | 1080×2340, 391프레임. `onFinish` 6.501초에 1회, `CLOCK_TICK` 햅틱 호출 기록. `preview/compose.mp4`가 이 녹화입니다 |

**돌려 보지 못한 것**
- **실제 안드로이드 기기·에뮬레이터**: 작업 환경에 기기와 KVM이 없어 에뮬레이터를 띄울 수 없었습니다.
  - 그래서 `compose.mp4`는 기기 녹화가 아니라 Robolectric(안드로이드와 같은 Skia를 CPU에서 실행) 녹화입니다.
  - GPU(HWUI) 렌더와는 안티앨리어싱이 미세하게 다를 수 있습니다.
  - 글꼴은 Robolectric 기본 Roboto라서, 기기 글꼴로 보면 한글 소개 문구 모양이 조금 다릅니다.
  - 녹화에서는 앱의 투어 화면 대신 #0B0B1A 단색을 깔았습니다.
- **중급 폰 60fps**: 실기기 프로파일링을 하지 못했습니다.
  - 코드상으로는 프레임당 할당과 파싱이 없습니다.
  - 매 프레임 계산량은 리본 3개 × 257단면 갱신과 세그먼트 47개의 워프입니다.
  - 그리기는 `drawPath` 최대 약 94회(세그먼트 47 + 음영)이고, 착지가 끝나면 6회로 줄어듭니다.
  - Snapdragon 7 계열 기기에서 GPU 렌더링 프로파일로 한 번 확인해 주세요.
- **햅틱 체감**: JVM에서는 호출만 기록되고 진동은 나지 않습니다.
- **lottie-android 실기기 재생**: 같은 라이브러리를 JVM에서 돌렸습니다. 하드웨어 가속 캔버스에서의 재생은 직접 확인하지 못했습니다.

## 다시 만들기

```bash
cd lottie/source
pip install numpy skia-python pillow           # 엔진·미리보기 렌더 (skia-python 은 libEGL 필요)
python3 build_deliverables.py A --harness ../../verify
#  → lottie/opening.json, compose/EvoOpening.kt 의 생성 상수 블록, preview/*, build_report.json
```

- `verify/android`
  - Android SDK(`local.properties`의 `sdk.dir`)가 필요합니다.
  - `./gradlew :app:testDebugUnitTest --tests '*EvoParity*'|'*LottieRender*'|'*RecordFrames*'`로 개별 실행할 수 있습니다.
- `verify/web`: `npm ci` 후 `node render_lottie_web.mjs JSON OUTDIR --bg '#0B0B1A'`
- 연출 값
  - 연출 값은 `lottie/source/choreo.py` 한 곳에 있습니다.
  - Compose 쪽 숫자는 `gen_kotlin_consts.py`가 `EvoOpening.kt`의 `BEGIN/END 생성된 상수` 블록에 넣습니다. 손으로 고치지 말고 생성기를 돌려 주세요.

  - 세그먼트 사이 색 줄무늬를 없앴습니다.
  - 착지 마커를 눈에 멈추는 시점으로 옮겼습니다.
- 의뢰인 선택은 A이고, B는 폐기했습니다.
